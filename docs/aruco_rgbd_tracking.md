# RGB-D 기반 ArUco 상대좌표 트래킹 — 방식·구조·문제 해결 기록

`aruco_test_gemini.py`에 대한 학습용 문서.
D405(RGB-D) 카메라로 **기준 마커(ID 0)** 좌표계에서 **타겟 마커(ID 1)** 의 3D 위치를
실시간 추적한다. 카메라가 움직여도 base 마커 기준의 상대좌표는 불변이어야 한다는 것이
이 시스템의 핵심 요구사항이자, 정확도를 검증하는 방법이다.

---

## 1. RGB-D의 기초 개념

### 1.1 depth 이미지란

- `16UC1` (16비트 unsigned) 이미지. 각 픽셀 값 = 그 픽셀 방향에 있는 표면까지의
  **광축(Z) 방향 거리, mm 단위**. 광선을 따라 잰 거리(유클리드 거리)가 아니라 Z 성분이다.
- 값 `0` = 측정 실패(무효). depth를 쓸 때는 항상 0을 걸러내야 한다.

### 1.2 aligned depth

RGB 카메라와 depth 카메라는 물리적으로 다른 위치에 있어서, 같은 픽셀 좌표가
서로 다른 지점을 본다. `aligned_depth_to_color` 토픽은 depth를 **컬러 카메라 시점으로
재투영한 것**이라, 컬러의 (u,v) 픽셀과 depth의 (u,v) 픽셀이 같은 지점을 가리킨다.
따라서 **컬러 쪽 `camera_info`(내부 파라미터)를 depth 역투영에도 그대로 쓴다.**

### 1.3 역투영 (back-projection): 픽셀 + depth → 3D

핀홀 모델에서 3D 점 P = (X, Y, Z)는 픽셀 (u, v)로 투영된다:

```
u = fx · X/Z + cx,   v = fy · Y/Z + cy
```

역으로, 픽셀과 depth(Z)를 알면 3D를 복원할 수 있다:

```
x_n = (u - cx) / fx      ← 정규화 좌표 (렌즈왜곡 보정 포함: cv2.undistortPoints)
y_n = (v - cy) / fy
P_cam = (x_n·Z,  y_n·Z,  Z)
```

이 한 줄이 RGB-D의 존재 이유다. **단안 카메라는 방향만 알고 거리를 모르는데,
depth가 거리를 직접 준다.** 코드에서는 `cv2.undistortPoints`로 (x_n, y_n)을 구한 뒤
Z를 곱한다 (`process_frame`의 [2단계]).

### 1.4 이 프로젝트에서 확인된 depth의 성질 (D405 실측)

- **위치 반복 정밀도: mm 수준.** 같은 자리로 카메라를 되돌리면 P_cam이 1~3mm 안에서 재현됐다.
- **거리·각도 의존 bias 존재.** 18cm에서 잰 값과 47cm에서 잰 값은 수 mm 다르게 치우친다.
  랜덤 노이즈는 평균으로 없앨 수 있지만 bias는 평균해도 안 사라진다 — 최종 오차 바닥의 정체.
- D405 최적 범위는 근거리(~50cm 이내). 멀어질수록 노이즈와 bias 모두 커진다.

## 2. 시스템 구조 (ROS 2)

```
/camera/d405/color/camera_info ──▶ info_cb   : K(3×3), 왜곡계수 D 1회 저장 후 구독 해제
/camera/d405/color/image_raw ────▶ color_cb  : 최신 컬러 프레임 버퍼
/camera/d405/aligned_depth_to_color/image_raw ▶ depth_cb : 최신 depth 프레임 버퍼
                                                (BEST_EFFORT QoS — 센서 데이터용)
30Hz 타이머 ──▶ process_frame() : 검출·계산·시각화·키 입력 전부 담당
```

- 콜백은 수신만 하고, 처리는 타이머에서 한다. rclpy 기본 실행기는 단일 스레드라
  콜백과 타이머가 동시에 돌지 않아 락 없이 안전하다.
- 컬러/depth는 **동기화 없이 각자 최신 프레임**을 쓴다. 정지 상태 측정에는 문제없고,
  움직이는 중의 좌표가 중요해지면 `message_filters.ApproximateTimeSynchronizer`로
  타임스탬프 짝을 맞추는 게 정석이다. (의도적으로 미룬 부분)

## 3. 좌표계와 변환

세 개의 좌표계가 등장한다:

- **카메라 좌표계**: 원점 = 카메라 광학 중심, +Z = 시선 방향
- **base 좌표계**: 원점 = ID 0 마커 중심, Z축 = 마커 면의 법선
- (픽셀 좌표계: 이미지의 u, v)

`solvePnP` 계열이 주는 (rvec, tvec)은 "마커 좌표 → 카메라 좌표" 변환이다:

```
P_cam = R · P_base + t          T_cam2base = [ R  t ]
                                             [ 0  1 ]   (4×4 동차 변환)
```

우리가 원하는 건 반대 방향(카메라에서 본 타겟을 base 기준으로)이므로 역변환을 쓴다:

```
P_base = T_cam2base⁻¹ · P_cam
```

카메라가 어디로 움직이든, base 마커와 타겟이 그대로면 P_base는 상수여야 한다.
**이 불변성이 깨지는 정도가 곧 시스템의 오차다.**

## 4. 처리 절차 (매 프레임)

```
① ArUco 검출 (APRILTAG_36h11) ─ 컬러 이미지에서 ID 0, ID 1의 코너 픽셀 획득
② base(ID 0) 자세 = PnP + depth 융합           ┐
   ├ solvePnPGeneric(IPPE_SQUARE): 두 해 획득   │ 5절에서 상세
   ├ depth 평면 법선으로 올바른 해 선택 (flip 해소) │
   ├ 기울기: 마커 Z축을 depth 법선에 정렬          │
   └ 위치: 중심 픽셀 + depth 역투영               ┘
③ 타겟(ID 1) 위치 = 중심 픽셀 + depth 역투영 → P_cam
④ P_base = T_cam2base⁻¹ · P_cam
⑤ 5-프레임 median 필터 (화면 표시용)
⑥ 스페이스바: 30프레임 수집 → 평균±표준편차, 기준점 대비 오차 출력
```

### 역할 분담의 설계 원칙

| 측정량 | 출처 | 이유 |
|---|---|---|
| base 위치 | 픽셀 + depth | depth가 mm급으로 정확, PnP 스케일 오차 회피 |
| base 기울기 (Z축) | depth 평면 피팅 | 작은 마커의 PnP 기울기는 관측성이 나쁨 |
| base 면내 회전 | PnP | 면내 회전은 작은 마커도 정확, depth로는 못 구함 |
| 타겟 위치 | 픽셀 + depth | base 위치와 같은 방식 → 계통오차 상쇄 |

**타겟의 ArUco는 "픽셀 위치를 찾는 검출기"로만 쓰인다.** 3D 계산에 마커 크기나
PnP가 안 들어가므로, 타겟 검출을 색상·딥러닝 등 다른 방식으로 바꿔도
"중심 픽셀 하나"만 주면 파이프라인이 그대로 동작한다.

## 5. 무슨 문제를 어떻게 해결했나 (시간순)

초기 상태의 오차: 정지 위치 재방문 시 **±10~20cm**. 최종: **±1cm대**.
각 단계는 "증상 → 진단 → 수정" 순서로 정리한다. 진단 방법 자체가 이 문서의 핵심이다.

### 문제 1 — 자세 락킹: 첫 프레임의 해에 영원히 갇히는 구조

- **원래 코드**: 첫 프레임에서 PnP를 풀고, 이후엔 그 결과를 initial guess로
  iterative refine만 반복 (`useExtrinsicGuess=True`).
- **문제**: 첫 해가 틀리면(아래 flip 참조) 계속 틀린 해 주변만 맴돈다.
  오검출 한 번으로 오염되면 회복 불가.
- **수정**: 매 프레임 독립적으로 추정하되, 해 선택을 기하학적으로 검증 (문제 2).

### 문제 2 — 평면 마커의 flip ambiguity (지배적 오차원)

- **증상**: 카메라를 같은 자리로 되돌려도 오차가 ±18cm까지 널뜀.
- **진단**: 스페이스바 로그에 중간 계산량을 추가해 오차를 분해했다.
  같은 위치 재방문 시 —
  - P_cam (depth 기반 타겟 위치): **mm 단위 재현** → depth 무죄
  - base_t (base 위치): **mm 단위 재현** → 위치 무죄
  - base_r (base 회전): **~24° 점프** → 범인 확정
- **원리**: 평면 사각형의 원근 투영에는 기울기 부호가 다른 **두 개의 해**가 수학적으로
  존재한다(planar pose ambiguity). 마커가 작게 찍히면(3cm 마커 @ 45cm ≈ 30픽셀)
  두 해의 reprojection error가 거의 같아져 선택이 사실상 랜덤이 된다.
  회전 오차 θ는 `오차 ≈ θ × (base↔타겟 거리)`로 증폭된다 — 24° × 50cm ≈ 20cm. 관측치와 일치.
- **수정**: `solvePnPGeneric`으로 두 해를 모두 받고, **depth로 잰 마커 평면의 법선**과
  각 해의 마커 Z축(`R[:,2]`)을 내적해 일치하는 쪽을 선택. RGB만으로는 풀 수 없는
  모호성을 depth라는 독립 센서가 물리적으로 해소해 준다. **RGB-D 융합의 전형적 사례.**

### 문제 3 — 마커 크기 오기입 (5cm로 코딩, 실물은 3cm)

- **문제**: PnP의 거리(tvec)는 마커 크기에 **정비례**한다. 5/3 = 1.67배 뻥튀기된
  base 거리가 계산되고 있었다. 타겟은 depth 기반(실제 스케일)이라 둘이 안 맞고,
  그 불일치가 카메라 시점마다 다른 방향의 오차로 나타났다.
- **교훈**: 마커 크기는 **검은 테두리 바깥 변**을 실측해서 넣어야 하며,
  크기 오차 %가 그대로 거리 오차 %가 된다.
- **후속**: [보정 2]에서 base 위치를 depth 기반으로 바꾸면서 이 민감도 자체를 제거했다.
  (현재 마커 크기는 면내 회전에만 관여하고, 면내 회전은 크기 불변)

### 문제 4 — 왜곡 모델 불일치

- **문제**: 원래 코드는 타겟 역투영에 `inv(K) @ [u, v, 1]`을 썼다 — 렌즈 왜곡 무시.
  반면 base의 solvePnP는 왜곡계수를 사용. 두 계산이 서로 다른 카메라 모델을 쓰면
  화면 가장자리에서 systematic 오차가 생긴다.
- **수정**: 모든 역투영을 `cv2.undistortPoints`로 통일. (D405 컬러는 왜곡계수가
  0으로 퍼블리시되는 경우가 많아 실효는 작았지만, 모델 일관성은 원칙 문제)

### 문제 5 — 측정 소스 혼용: base는 PnP-z, 타겟은 depth-z

- **문제**: 두 방식은 서로 다른 bias를 갖는다. 상대좌표를 만들 때 bias가 상쇄되지 않고
  그대로 남는다.
- **수정**: base 위치도 타겟과 **완전히 같은 방식**(중심 픽셀 + depth 중간값 + 역투영)으로.
  같은 센서·같은 방식으로 잰 두 값의 차이는 계통오차가 상당 부분 상쇄된다.
  **오차를 없애기 어려우면 상쇄되게 설계하라.**

### 문제 6 — 작은 마커의 기울기 관측성 한계

- **증상**: flip을 잡은 뒤에도 시점 간 ±1.5~4cm systematic 오차 잔존.
  base가 멀어질수록(45→66cm) 악화.
- **원리**: 30픽셀짜리 마커로 기울기를 재는 것은 원리적으로 부정확하다 (±2~5°).
  평면 피팅의 각도 정확도는 **재는 영역의 폭에 반비례**한다.
- **수정 1 (기울기 교체)**: PnP 기울기를 버리고, depth 평면 법선을 마커 Z축으로 사용.
  PnP의 Z축을 depth 법선으로 보내는 **최소 회전**(Rodrigues 공식)을 적용해
  면내 회전은 보존한다:
  ```
  v = z_pnp × n_depth,  c = z_pnp · n_depth
  R_align = I + [v]ₓ + [v]ₓ² / (1 + c)
  R_new = R_align · R_pnp     → R_new의 Z축 = n_depth, 면내 성분 유지
  ```
- **수정 2 (피팅 영역 확장)**: 마커가 평평한 면에 붙어 있으면 주변 면도 같은 평면이다.
  피팅 영역을 마커의 2배로 확장(`scale=2.0`)하고, 면을 벗어난 픽셀(배경)은
  "피팅 → 잔차 5mm 초과 기각 → 재피팅" 반복으로 자동 제거. 폭이 2배가 되면
  법선 정확도도 ~2배 — **물리 마커를 키운 것과 (기울기에 한해) 동일한 효과를 공짜로** 얻는다.
- **결과**: X ±0.5cm, Y ±1cm, 원위치 복귀 sub-cm. σ도 절반 이하로 감소.

### 문제 7 — 측정 방법론: 순간값으로는 노이즈와 bias를 구분할 수 없다

- **문제**: 스페이스바가 순간값 하나를 찍으면 "튀는 건지(랜덤) 치우친 건지(계통)" 판별 불가.
- **수정**: 스페이스바 → **30프레임 수집 → 평균 ± 표준편차** 출력.
  - σ = 그 자리의 랜덤 노이즈 크기. 평균을 쓰면 √30 ≈ 5.5배 줄어든다.
  - 시점 간 error가 σ보다 훨씬 크면 → 계통오차 (필터로 못 없앰, 원인 제거 필요)
  - stale 감지(마지막 측정이 0.5초 이상 오래되면 경고)도 추가 — 타겟을 놓친 채
    옛 값을 측정으로 오인하는 것을 방지.

## 6. 남은 한계와 개선 여지

| 항목 | 내용 |
|---|---|
| 현재 오차 바닥 | ±1~1.5cm (시점 간 systematic). 원인은 D405 depth의 거리·각도 의존 bias — 알고리즘이 아닌 센서 특성 |
| 더 줄이려면 | ① 기준 depth bias 캘리브레이션(실측 대비 보정 테이블) ② base↔타겟 거리(lever arm) 축소 ③ base 마커 확대 또는 ChArUco 보드 |
| 시간 동기화 | 컬러/depth가 비동기. 움직이는 중의 좌표가 필요해지면 `ApproximateTimeSynchronizer` 도입 |
| origin 잡는 요령 | 카메라가 base·타겟 모두에 가까운 시점(base ~25–35cm)에서 잠글 것. 먼 시점에서 잡으면 bias가 한쪽으로 몰려 보인다 |
| 평면 피팅 전제 | `scale=2.0` 확장은 마커 주변 ~1.5cm가 마커와 같은 평면일 때 유효. 면이 넉넉하면 scale=3까지 상향 가능 |

## 7. 핵심 교훈 요약

1. **depth는 위치에 강하고, 작은 평면 마커는 자세(기울기)에 약하다.**
   각자 잘하는 것만 시켜라: 위치·기울기 = depth, 면내 회전 = PnP.
2. **회전 오차는 lever arm을 타고 위치 오차로 증폭된다** (오차 ≈ θ × 거리).
   기준 좌표계의 회전 정확도가 시스템 전체 정확도를 지배한다.
3. **오차를 분해해서 범인을 특정하라.** 최종 오차만 보면 아무것도 알 수 없다.
   중간 계산량(P_cam, base_t, base_r)을 로그로 찍고 "무엇이 재현되고 무엇이 튀는지"를
   보면 원인이 하나로 좁혀진다.
4. **랜덤 노이즈와 계통오차는 다르게 싸운다.** 랜덤은 평균/median으로 죽지만,
   계통은 원인을 제거하거나 상쇄되게(같은 센서·같은 방식) 설계해야 한다.
5. **물리 상수(마커 크기)는 실측하라.** 코드가 아무리 맞아도 입력 상수가 틀리면
   그 비율만큼 정확히 틀린다.
6. **평면 마커 PnP에는 항상 flip ambiguity가 있다.** 마커가 작거나 정면에 가까울수록
   심하다. `solvePnPGeneric`으로 두 해를 받아 독립 정보(depth, 시간 연속성 등)로
   선택하는 것이 안전하다.
